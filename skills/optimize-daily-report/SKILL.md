# 修改成优秀日报：日报优化通用原则

## 触发场景

当用户给出一份日报（或周报中的「今日完成」），并要求优化、改写、润色、改成优秀日报时，按本技能改写后输出。只改用户给出的日报正文，不扩写未提供的工作。

## 核心目标

日报的核心价值是让阅读者在最短时间内明确：今日完成了什么、完成状态如何、产出价值何在。所有优化动作均围绕这三个问题展开。

## 原则一：小标题必须包含明确动作与结果

小标题不能仅呈现名词或事项名称，必须包含执行动作与最终结果，确保阅读者仅看小标题即可判断本条事项的核心成果，无需向下阅读正文才能获取关键信息。

## 原则二：每条事项必须有可确认的完成状态

所有工作事项必须标注明确的完成状态，避免使用模糊的过程性描述。状态需可被直接确认，不存在歧义，阅读者无需追问即可判断事项是否完结。

可直接确认的状态只用下面四类：

- 已完成
- 进行中（必须带当前进度，或已经交付的中间结果）
- 未完成（必须带卡在哪一步；主句仍写已经做到哪里）
- 已取消

「推进中」「持续跟进」「基本完成」「大致搞定」「处理中」不能作为完成状态。

## 原则三：表述重心始终放在动作与结果上

背景信息、困难说明、过程描述可以补充，但不能替代结果表述。句子核心必须围绕执行动作与最终成果展开，避免以原因、困难作为句子的表述重心。

## 原则四：去除冗余修饰与模糊表述

删除不影响核心意思的冗余词汇，替换所有无法被验证的模糊描述，确保每句话的信息密度最高，无多余修饰，无歧义空间。

无法验证、必须替换或删除的词包括：相关、一些、部分、基本、大致、进一步、持续、有效、顺利、较好、一定程度、进行了处理。

## 优先级规则

仅修改影响信息传达准确性的硬性问题，包括状态模糊、结果缺失、重心偏移、冗余表述。不涉及同义词替换、语序微调等不影响核心信息传达的润色类修改。

## 改写步骤

1. 保留原文的章节、条目顺序、人名、数字、时间和已经写明的事实。
2. 逐条对照四条原则，只改硬性问题。
3. 原文没有的结果、数据、状态不得编造。无法从原文确认状态时，该条末尾标「状态待确认」，并在文末「待补充」中列出缺的是状态还是结果。
4. 输出前逐条核对：小标题能否独立读懂成果；状态是否属于四类之一；主句是否是动作和结果；有没有残留模糊词；改动是否都属于硬性问题。

## 输出

先输出改写后的完整日报，结构与原文一致。再输出「修改说明」，每条只写触发的原则和改写原因。没有硬性问题时，日报原文照出，修改说明写「无需修改」。有无法确认的状态或结果时，最后加「待补充」。

## 示例

原则一。原文小标题：`用户登录模块`。改为：`完成用户登录模块开发，已提测`。

原则二。原文：`正在推进需求评审`。改为：`需求评审已完成，结论为通过`。若原文看不出是否通过：`需求评审已召开。状态待确认`。

原则三。原文：`由于接口不稳定，联调遇到困难`。改为：`完成联调，定位并修复 3 处接口超时`。原文没有修复结果时：`联调未完成，卡在接口超时。状态待确认`。

原则四。原文：`基本上大致完成了相关的一些优化工作`。改为：`完成列表查询优化，接口耗时从 800ms 降至 200ms`。原文没有耗时数据时，不补数字，只保留能够确认的动作和结果。

优先级。原文已经是「完成订单导出，支持按日期筛选，已上线」。不得改成「上线订单导出功能，现已支持日期筛选」。
